# Wireless Data Protocol (WDP) - Version 1.0

## 1. Introduction

The Wireless Data Protocol (WDP) is a custom protocol designed for communication between in-game User Equipment (UE) and Access Points (AP) over the wireless network.

## 2. Message Format

### 2.1. Encoding

All encoding and decoding of messages uses `textutils.serialiseJSON`/`textutils.unserialiseJSON` functions to convert between Lua tables and JSON strings.

### 2.2. Unauthenticated Message Structure

The following packet structure is used for all messages:

```lua
{
    version: string,  -- `1.0` for the current version of the WDP protocol
    type: string,     -- The type of the message
    sequence: number, -- A sequence number for tracking and relating message order
    payload: object,  -- The actual data being sent
}
```

### 2.3. Authenticated Message Structure

The following packet structure is used for all messages in an authenticated session:

```lua
{
    version: string,   -- `1.0` for the current version of the WDP protocol
    type: string,      -- The type of the message
    sequence: number,  -- A sequence number for tracking and relating message order
    payload: object,   -- The actual data being sent
    signature: string, -- A cryptographic signature derived from the session token for message integrity and authenticity
}
```

This must be used after an `auth_success` message has been received and the session token has been established.

## 3. Message Security

### 3.1. Authentication

Authentication makes use of a HMAC function to ensure the integrity and authenticity of messages exchanged between the UE and AP.

The following fields are used in the computation of the MAC:

| Field | Description |
|-------|-------------|
| `K` | A shared secret key known only to the UE and AP. |
| `role` | A string indicating the role of the sender, either `"client"` for the UE or `"server"` for the AP. |
| `C` | The UE's Rednet ID. |
| `S` | The AP's Rednet ID. |
| `Nc` | A nonce generated by the UE for the authentication challenge. |
| `Ns` | A nonce generated by the AP for the authentication challenge. |
| `MAC` | The MAC is computed using the formula below. |

The MAC is computed using the following formula:

```lua
HMAC(K, role || C || S || Nc || Ns)
```

### 3.2. Session Token

The session token is a unique identifier generated by the AP upon successful authentication. It is used to maintain the state of the authenticated session and is included in all subsequent messages exchanged between the UE and AP.

### 3.3. Message Signature

The message signature is used to ensure the integrity and authenticity of messages exchanged during an authenticated session.

It is computed using following formula:

```lua
signature = HMAC(session_token, message_payload)
```

## 4. Message Types

The following message types are defined in the protocol:

| Type | Direction | Description | 
|------|-----------|-------------|
| `error` | UE <-> AP | Indicates an error occurred during communication. |
| `auth_init` | UE -> AP | The UE initiates an authentication request to the Access Point. |
| `auth_challenge` | AP -> UE | The Access Point sends an authentication challenge to the User Equipment. |
| `auth_response` | UE -> AP | The User Equipment responds to the authentication challenge. |
| `auth_success` | AP -> UE | The AP indicates that authentication was successful. |
| `auth_failure` | AP -> UE | The AP indicates that authentication failed. |
| `submit_data` | UE -> AP | The UE submits data to the Access Point. |
| `deliver_data` | AP -> UE | The AP delivers data to the User Equipment. |
| `ack` | UE <-> AP | Acknowledgment of received messages. |
| `ping` | UE -> AP | Request to test the connection with the Access Point. |
| `pong` | AP -> UE | Response to a `ping` message, confirming the connection is active. |

### 4.1. `error` Message

The `error` message is sent by either the UE or the AP to indicate that an error occurred during communication.

```lua
{
    sequence: number, -- The sequence number of the message that caused the error
    code: number,     -- Error code indicating the type of error
    message: string,  -- A human-readable description of the error
}
```

#### 4.1.1. Error Codes

The following error codes are defined for the `error` message:

| Code | Description |
|------|-------------|
| 100 | Invalid Message Format |
| 101 | Unsupported Version |
| 102 | Invalid Message Sequence Number |
| 103 | Invalid Message Signature |

### 4.2. `auth_init` Message

The `auth_init` message is sent by the UE to the AP to initiate an authentication request.

```lua
{
    nonce: string, -- The Nc nonce, See § 3.1 for details
}
```

### 4.3. `auth_challenge` Message

The `auth_challenge` message is sent by the AP to the UE to provide an authentication challenge.

```lua
{
    nonce: string, -- The Ns nonce, See § 3.1 for details
    mac: string,   -- The MAC computed by the AP, See § 3.1 for details
}
```

### 4.4. `auth_response` Message

The `auth_response` message is sent by the UE to the AP in response to the authentication challenge.

```lua
{
    mac: string, -- The MAC computed by the UE, See § 3.1 for details
}
```

### 4.5. `auth_success` Message

The `auth_success` message is sent by the AP to the UE to indicate that authentication was successful.

```lua
{
    session_token: string, -- A token representing the authenticated session
    msisdn: string,        -- The MSISDN assigned to the UE
}
```

### 4.6. `auth_failure` Message

The `auth_failure` message is sent by the AP to the UE to indicate that authentication failed.

```lua
{
    code: number,   -- Error code indicating the reason for authentication failure
    reason: string, -- A human-readable description of the reason for authentication failure
}
```

### 4.7. `submit_data` Message

The `submit_data` message is sent by the UE to the AP to submit data.

```lua
{
    service: string,       -- The service for which the data is being submitted
    data: object,          -- The data being submitted by the UE
}
```

### 4.8. `deliver_data` Message

The `deliver_data` message is sent by the AP to the UE to deliver data.

```lua
{
    service: string,       -- The service for which the data is being delivered
    data: object,          -- The data being delivered to the UE
}
```

### 4.9. `ack` Message

The `ack` message is sent by either the UE or the AP to acknowledge the receipt of a message.

```lua
{
    sequence: number, -- The sequence number of the message being acknowledged
}
```

### 4.10. `ping` Message

The `ping` message is sent by the UE to the AP to test the connection.

```lua
{
    timestamp: number, -- The timestamp when the ping was sent
}
```

### 4.11. `pong` Message

The `pong` message is sent by the AP to the UE in response to a `ping` message.

```lua
{
    timestamp: number, -- The timestamp when the pong was sent
}
```
